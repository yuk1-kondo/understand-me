# UX / design review — Understand Me, 2026-11-23

Scope: `evenhub/` (the product — glasses canvas 576×288 + phone WebView) and
`app/` (secondary browser demo). Method: read of `evenhub/src/main.ts`,
`app/*`, plus pixel-level analysis of the two captured framebuffers
(`demo-assets/01-caption-view.png`, `02-checksum-card.png`) — every lit row
band was measured, so the geometry findings below are from the actual LVGL
output, not the code's intent.

Severities: **high** = broken or actively misleading on the lens today,
**medium** = real usability problem for a wearer, **low** = known trade-off
or polish. Fixed items are marked; the rest are deliberately left alone.

## Measured display facts (basis for every finding)

- Firmware text line: glyph ~19–20 px tall, line pitch ~27 px, ~24
  full-width glyphs per 576 px row (~22 px/glyph observed).
- Caption view bands (before): header y6–25; old captions y43–115 (3 lines);
  latest y195–213; footer line 1 y256–277; **footer line 2 y286–287 — two
  pixel rows survived**, i.e. clipped to nothing by the canvas edge.
- Checksum card bands (before): card text y43–115; list item 1 y182–221
  (focus box), item 2 y234–251; **footer y270–287, bottom clipped**.
- Vertical bar segments flank the header-right container (`| LIVE |`,
  `| 要確認 |`) and appear at the right edge of short containers — an LVGL
  scroll nub. Experimentally, it appears on any text container with
  `height < ~36 px` (one 27 px line + padding ≈ 35 px makes the content
  "scrollable"); at h≥36 it disappears. Widening a container does **not**
  help — widths are clamped to the canvas, so the nub just lands at x≈569.
  Fix applied: every text container is now ≥36 px tall, and content is
  clipped to its line budget so it can never outgrow the container.

## Design rules (text tokens — apply to any future container work)

**Canvas.** 576×288, monochrome green. Brightness is the only emphasis
channel: `textColor` 0–4, default 4 when omitted. There is no font-size,
weight, or style control — size it once, it never changes.

**Type metrics (measured, simulator LVGL build):**
- line pitch ~27 px, glyph ~19–20 px tall
- ~24 full-width glyphs per line at 576 px (≈22 px/glyph; half-width ~half)
- budget: **LINE = 24 chars** per row; allow N lines = N×LINE chars

**Container budget.** Every text container must satisfy BOTH:
- `height ≥ 36` — below that LVGL considers the content scrollable and
  draws a right-edge scroll nub (the `|`-artifacts; verified: 32 shows the
  nub, 36 does not)
- `height ≥ (#lines × 27) + 8` — content taller than the container clips
  at the canvas edge (that's what ate both footers)
Keep `yPosition + height ≤ 288`.

**Layout skeleton (both views):**
- header band y0–36: title left (x0 w400), state right (x400 w172, color 2)
- body starts y40
- footer is always **one** line, dim, and only drawn when it documents a
  live affordance — a hint for an action that doesn't exist is noise on a
  HUD

**Brightness ladder:**
- 4 — the thing the wearer must read or act on right now (latest caption,
  pending-card alert, card values, transient success message)
- 3 — secondary state (`要確認`, slot line)
- 2 — context and affordances (older captions, hints, badges, waiting text)
- never put actionable information below 3

**Hierarchy rules.** The newest caption is visually isolated from history
(own bright container, gap above). The pending-card alert owns a line that
is blank when idle — appearance = notification. On the checksum card the
labels are furniture (color 2); the diff values are the decision (color 4).

**Glyphs.** Use only glyphs verified in the firmware font. Verified:
full/half-width Japanese, `：`, `　`, `▲`, `↑↓`, `…` (re-verified this
session — zero glyph warnings in the simulator log). Known-bad: `✓`
(U+2713). Anything else needs a simulator glyph check before it ships.

**Motion.** None — no blinking, pulsing, or transitions anywhere. State
change is communicated by content appearing, not by animation. On a
monochrome HUD over the real world, motion is a cost, not a reward.

**Interaction contract (unchanged):**
- captions view: tap → checksum card
- card: swipe = move list focus, tap = select focused item,
  scroll-past-top → back to captions, double-press → system exit dialog
- exactly one `isEventCapture` container per page (capold / choices)
