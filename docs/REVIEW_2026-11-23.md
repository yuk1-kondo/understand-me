# Code review — Understand Me, 2026-11-23

Scope: `backend/` (core, discord_bot, telegram_bot), `evenhub/`, `app/`.
Method: full read of every source file plus the verified run notes in
`demo-assets/CAPTURE_NOTES.md`. Severities: **high** = broken behavior today,
**medium** = real defect or landmine, **low** = worth knowing, not worth
blocking a demo on.

## Findings

### High

| # | Severity | Location | Finding |

The file describes an environment that does not work. |

### Medium

| # | Severity | Location | Finding |
|---|----------|----------|---------|
| M1 | medium | `backend/discord_bot/requirements.txt` | `faster-whisper` and `numpy` are missing even though `STT_PROVIDER=whisper` is implemented in `stt_interface.py:60-91` and is the selected provider. A fresh `pip install -r requirements.txt` crashes on the first utterance (`ImportError` inside `transcribe`). `aiohttp` is imported directly by `receiver.py` but only arrives transitively via discord.py. |
| M2 | medium | `backend/telegram_bot/bot.py:190` | `get_stt_provider()` is called per voice note, constructing a new `WhisperFileSTTProvider` each time → the multi-GB `large-v3-turbo` model reloads on **every** message. The provider should be cached (lazy singleton). |
| M3 | medium | `app/app.js:90-97` | `pollCaptions` only accepts `{captions: [...]}`, but `GET /captions` returns a bare array (`main.py:113-116`). Against the real backend the browser demo shows `DEMO` and no captions forever. The evenhub port already accepts both shapes (`evenhub/src/main.ts:175`); this file was not updated in step. |
| M4 | medium | `backend/discord_bot/receiver.py:208-248` | `_handle_utterance` posts via `asyncio.get_running_loop().create_task()`. When the segmenter flushes from `cleanup()` (called on the library's packet thread, not the loop) there is no running loop → `RuntimeError` → the final utterance's caption is silently dropped. Separately, the Whisper transcribe runs **synchronously on the event loop** when invoked via `flush_idle` — a several-second CPU call that stalls caption posting, broadcasts, and the flush loop itself. |
| M5 | medium | `backend/discord_bot/receiver.py:97-129` | `SpeakerSegmenter._buffers`/`_last_seen` are mutated by `feed()` on the voice_recv packet thread while `flush_idle()` iterates/pops them on the event loop. No lock → torn utterances or lost audio under load. |
| M6 | medium | `backend/core/main.py:70-87` | `last_instruction` is never cleared. Once speaker A instructs, **every** instruction-like utterance from speaker B is treated as a paraphrase of A's stale instruction forever — B can never issue her own instruction, and stale comparisons produce wrong cards (the "messy card" seen in CAPTURE_NOTES). |
| M7 | medium | `backend/core/stt.py:48-53` | `get_stt()` returns `UnconfiguredSTT` for **any** non-`"fake"` value — including `whisper` (a real provider now) and plain typos. Misconfiguration is silent; the bot packages' `get_stt()` raise `ValueError` on unknown names. |
| M8 | medium | `evenhub/src/main.ts:24` | `BACKEND` is hardcoded to `http://localhost:8000`. There is no way to point a build at another backend (alternate port, LAN IP for hardware) without editing source. Needs a build-time override (Vite env) with the same default. |

## Verdict per component

- **backend/core** — Sound demo-grade API; extraction and diff logic are tested and correct. The weak point is the session state around `last_instruction` (M6) and the silently-swallowing `get_stt` (M7). Fix and keep.
- **backend/discord_bot** — `receiver.py` is carefully and defensively written and was proven live today. The real defects are the dependency file (H2, M1) and the loop/threading handling around `_handle_utterance` (M4, M5). Solid after those fixes.
- **backend/telegram_bot** — Clean structure, but the ship-blocker response-shape bug (H1) means its checksum flow never worked against this backend. Per-message provider construction (M2) would make it unusably slow even once fixed. Needs both fixes before any demo.
- **app/** — Coherent standalone scaffold, now superseded by `evenhub/`. Its backend contract drifted (M3, L9); still worth fixing since it is the zero-build fallback demo.
- **evenhub/** — The strongest component: verified against the real simulator, honest README, correct SDK pin. Only practical wart is the hardcoded backend URL (M8). Keep the SDK at 0.0.14 (`^0.0.14` already resolves exactly to 0.0.14 in the lockfile).
