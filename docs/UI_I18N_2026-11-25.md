# UI 日英切替対応（2026-11-25）

提出版は海外審査員向けに **英語表示がデフォルト**。`?lang=ja` で従来の日本語 UI がそのまま出る。

## 変更点

### evenhub/src/main.ts / app/app.js / app/index.html / evenhub/index.html

- ハードコードされていた表示文字列（ボタン・接続状態・空状態・カード画面の固定文言・フッタヒント等）を `STRINGS` テーブル（ja / en）に分離し、`S` = `STRINGS[LANG]` 経由で参照するようにした。
- 言語決定：URL クエリ `?lang=` が最優先。`?lang=ja` → 日本語、それ以外（指定なし含む）→ **英語**。`document.documentElement.lang` も連動。
- スタンドアロンデモ用のダミーデータ（字幕・確認カード）も言語別に用意（en は Thursday/Friday、slot は `deadline`）。
- `app/index.html` の静的文言は初期値を英語にし、render が触らない要素（タイトル・行ラベル・フッタヒント・カードアラート）に id を付けて起動時に JS から言語別文言を流し込む。
- カードのスロットラベル（`期限` 等）はバックエンド送信値をそのまま表示するため対象外（発話言語に追随する既存仕様）。

### evenhub/app.json

- `supported_languages` を `["en", "ja"]` に変更。

### backend/telegram_bot/bot.py

- 字幕テキストに日本語文字（かな・漢字）を含むかで日英を判定する `detect_lang()` を追加（`backend/core/checksum.py` の `looks_japanese` と同じ正規表現）。
- ボタン文言・案内文・スロットラベルを `STRINGS`（ja / en）に分離。言語は pending カードに保存し、callback（確定／訂正／stale 通知）でも継続利用。字幕が無い場面（`/start`・STT 未設定エラー・pending 無しの stale 通知）は英語。
- カード ID 付き `callback_data` の仕様と「この確認は更新されました」の stale 検知挙動は変更なし。

## 言語の切り替え方

| 対象 | 切替方法 |
|---|---|
| evenhub（グラス表示）・app/（ブラウザデモ） | URL に `?lang=ja` を付ける。省略時は英語 |
| Telegram ボット | 送った指示文の言語に自動追随（日本語文字を含めば日本語） |

## 検証結果

- `backend/core` pytest：**29 件すべてパス**（`.venv` の Python 3.14.6）
- `app/app.js`：`node --check` OK
- `backend/telegram_bot/bot.py`：専用 `.venv` で import OK、`detect_lang` / `format_confirmation` の日英出力を確認
- evenhub：`npm run build`（tsc + vite）成功、`evenhub pack` で `understand-me.ehpk` 再生成（41,558 bytes）
- `scripts/display_check.py`：**PASS**（英語デフォルト）。字幕表示 6,353 lit px、カード出現で 6.0% の画素変化を検出。成果物は `demo-assets/display-check-{captions,latest}.png`
- `?lang=ja` をシミュレータで目視確認：字幕画面・カード画面とも従来の日本語 UI が崩れず表示

## 補足

- display_check は初回実行時、フレームバッファ撮影がアプリのポーリング描画に先行するタイミング競合で 1 度 FAIL（画素差 1.9% < 閾値 2%）になった。手動再現では字幕・カードとも正常で、再実行で PASS。アプリ側の不具合ではない。
